Dolos v2 — Full Redesign Plan

Status: Draft — awaiting approval before implementation
Branch: feature/ui-managed-configs (to be created from master)
Version: v2.0.0 (breaking change)

1. Problem Statement

Dolos v1.x uses a mounted volume + directory tree pattern for configuration that has critical usability problems:

  1. Not editable via the Mythic UI — Configs live in a separate bind mount (dolos_profiles/) that the paperclip file browser cannot reach. Operators must SSH into the Mythic host to edit JSON files.

  2. Empty on first install — The volume starts empty. Operators see "No valid encoder profiles found" until they manually create JSON files from scratch or copy from disabled samples.

  3. Disabled samples with fake IPs — The shipped SAMPLE_PyEncoder has enabled: false and host: 192.168.1.100. Operators don't know what to change.

  4. Directory management complexity — Bypass profiles, SSH keys, and tools live in nested subdirectories (encoders/pyencoder/, ssh_keys/, tools/pyencoderv1/). Adding an encoder means creating a directory structure, not just a file.

  5. SSH keys in plaintext on the host — Private keys sit in bind-mounted flat files, not in Mythic's user secrets system.

  6. No UI feedback on config errors — Error messages about malformed configs only appear in container logs. The operator sees "(no profiles configured)" with no indication of why.

  7. Dev environment ≠ production — Local dev had tools, test configs, and directory structures that don't exist in a clean Docker install. Other users get an empty volume.

2. Architecture: Flat File Naming Convention

Core principle: The filename IS the metadata. No parsing needed until build time. You can enumerate, display, and sort configs by filename alone.

Naming Format

{NN}_{Type}_{Detail}.{ext}
Component Description
NN Two-digit sort order (00-99). All files with the same number belong to the same encoder group.
Type One of: Encoder, Bypass, Tool, SSHKey
Detail Human-readable label, underscores for spaces
ext .json for configs, no extension for SSH keys, .ps1/.sh for scripts

Example Directory Structure (inside /Mythic/configs/)

/Mythic/configs/
├── 00_Encoder_PyEncoder.json              
├── 00_Bypass_AMSI.json                   
├── 00_Tool_pyencoder_install.ps1         
├── 00_Tool_pyencoder_encode.py           
├── 00_SSHKey_operator_id_rsa             
├── 01_Encoder_Donut.json                 
├── 01_Tool_donut_install.ps1             
└── 01_SSHKey_jumpbox_id_rsa

What the Filename Tells You (No File Open Needed)

Filename Group Type Label Sort
00_Encoder_PyEncoder.json 00 Encoder PyEncoder 0
00_Bypass_AMSI.json 00 Bypass AMSI 0
00_Tool_pyencoder_install.ps1 00 Tool pyencoder install script 0
01_Encoder_Donut.json 01 Encoder Donut 1

Enumerating configs = os.listdir('/Mythic/configs/') + parse filenames. No directory traversal. No nested lookups. Done.

3. Default Encoder: PyEncoder for Windows

What Ships in the Docker Image

The default encoder is PyEncoder for Windows. It uses py.exe (the Windows Python launcher) and built-in Windows tools. This is NOT portable to Linux — it explicitly targets Windows.

The shipped config is enabled by default and nearly complete:

{
    "version": 2,
    "label": "PyEncoder",
    "enabled": true,
    "command": "py.exe C:\\tools\\dolos\\encoder.py {workdir}\\{input} {workdir}\\{output}",
    "ssh_host": "",
    "ssh_port": 22,
    "ssh_username": "",
    "ssh_password": "",
    "ssh_key_ref": "${00_SSHKey_operator_id_rsa}",
    "ssh_key_enabled": true,
    "timeout": 300,
    "success_string": "ENCODING_SUCCESS",
    "fail_string": "ENCODING_FAILED",
    "install_tools": true,
    "bypass_refs": [],
    "notes": "Windows-only encoder using py.exe. Fill in SSH credentials."
}

The operator only needs to add: SSH host, username, and their SSH public key on the target Windows machine. Everything else works out of the box.

PyEncoder Install Script

The 00_Tool_pyencoder_install.ps1 script does the following on the target Windows machine:

  1. Update winget using winget source update
  2. Install Python 3 via winget install Python.Python.3.12 (latest stable, compatible with our encoder)
  3. Create C:\tools\dolos\ directory
  4. Copy the encoder script — SFTP'd to the workdir first, then the install script moves it to C:\tools\dolos\encoder.py
  5. The encoder script is a simple Python script that reads input, applies transformation (initially: passthrough/copy, demonstrating the Dolos workflow), and writes output with the ENCODING_SUCCESS marker

This is NOT about building evasion or bypasses — it's a legitimate tool installation. The user enables PowerShell script execution (Set-ExecutionPolicy RemoteSigned or similar), runs the install script once, and they're ready to encode payloads.

Windows-Only Disclaimer

The PyEncoder profile and its tooling will be clearly documented as Windows-only. The command field uses py.exe (Windows Python launcher) and PowerShell install scripts. Linux/macOS users will need to create their own encoder profiles with appropriate commands (e.g. python3 /opt/dolos/encoder.py {workdir}/{input} {workdir}/{output}).

4. Other Encoders: Referenced in Docs, Not Shipped

Shellcode Ack (Liskit)

We will NOT ship a Shellcode Ack encoder profile or binary — it's a commercial product. Instead, the documentation will include a section:

Shellcode Ack by Liskit is a popular commercial shellcode encoder. Dolos can wrap payloads encoded with Shellcode Ack. To use it: 1. Purchase a license from liskit.com 2. Install the Shellcode Ack binary on your SSH server 3. Create an encoder profile in /Mythic/configs/: 02_Encoder_ShellcodeAck.json 4. Set the command to the Shellcode Ack CLI invocation 5. Point bypass profiles to any existing bypass configurations

Donut

Same pattern — document how to create a profile, link to the project, show example JSON. Don't ship the binary.

User-Created Encoders

The PyEncoder example serves as a template. Users copy it, change the number prefix, update the command, and they have a new encoder. Documentation will show step-by-step how to create an encoder profile for any tool.

5. File Type Schemas

NN_Encoder_{Label}.json

{
    "version": 2,
    "label": "PyEncoder",
    "enabled": true,
    "command": "py.exe C:\\tools\\dolos\\encoder.py {workdir}\\{input} {workdir}\\{output}",
    "ssh_host": "192.168.1.50",
    "ssh_port": 22,
    "ssh_username": "operator",
    "ssh_password": "",
    "ssh_key_ref": "${00_SSHKey_operator_id_rsa}",
    "ssh_key_enabled": true,
    "timeout": 300,
    "success_string": "ENCODING_SUCCESS",
    "fail_string": "ENCODING_FAILED",
    "install_tools": true,
    "bypass_refs": ["00_Bypass_AMSI.json"],
    "notes": "Windows-only. Uses py.exe launcher."
}

Key differences from v1: - Flat — ssh_host at top level, not nested under ssh_server - ssh_key_ref — ${VAR} syntax referencing the SSH key filename. Resolved via Mythic user secrets OR fallback to file content in configs/ - bypass_refs — Array of filenames, not directory paths - version: 2 — Schema version for forward compatibility - install_tools + matching NN_Tool_* files — tool scripts found by group number

NN_Bypass_{Label}.json

{
    "version": 2,
    "label": "AMSI Bypass",
    "enabled": true,
    "config": {
        "technique": "amsi_init_failed",
        "target_os": "windows"
    }
}

A labeled JSON blob. The encoder references it by filename. The builder reads this JSON and uploads it to the SSH workdir for the encoder command to use.

NN_Tool_{Label}.{ps1|sh|py}

Executable scripts. SFTP'd to the remote workdir before encoding if install_tools: true in the encoder profile. Found by matching the group number prefix.

NN_SSHKey_{Label} (no extension)

Raw PEM private key. At build time, Dolos resolves the ssh_key_ref: 1. Check Mythic user secrets (Hasura operationagentstorage) for ${00_SSHKey_operator_id_rsa} 2. If found, use the stored secret value 3. If not found, fall back to reading the file content from /Mythic/configs/00_SSHKey_operator_id_rsa

This lets operators store keys in Mythic's secure secrets OR as files accessible via the paperclip UI — their choice.

6. Config Resolution at Build Time

When building a payload:

  1. Enumerate → os.listdir('/Mythic/configs/') → parse filenames for type, group, label, sort order
  2. Read encoder JSON → get command, SSH details, bypass refs, tool flag
  3. Resolve ${VAR} references → query Hasura for stored secrets first, fall back to file content
  4. Read bypass JSON files → referenced by filename from bypass_refs array
  5. Upload matching NN_Tool_* scripts → found by group number match
  6. Connect SSH, upload, execute, download → same pipeline as v1

9. Persistent Config Across Reinstalls

Problem: mythic-cli install github overwrites InstalledServices/, destroying paperclip edits.

Solution: Dolos stores its active config state in Hasura agentstorage (key-value store accessible via Mythic RPC). On startup:

  1. Load files from /Mythic/configs/ (defaults baked into image)
  2. Check agent_storage for any overrides
  3. If agent_storage has configs → merge/replace file-based defaults
  4. If agent_storage empty → use file-based defaults as-is
  5. On config change (mtime trigger OR paperclip edit) → sync back to agent_storage

This means paperclip edits survive reinstalls. The flow: - Paperclip edit → file changes on disk → mtime trigger → reload → sync to agent_storage - Reinstall → files overwritten by image → on startup, agent_storage overrides restore operator's edits

13. Open Questions (Discuss Before Implementation)

  1. Should encoder scripts (.py, .ps1) live in /Mythic/configs/ alongside profiles? They're not configs — they're executables that get SFTP'd. Alternative: /Mythic/tools/ (also paperclip-accessible). Separate directory but still flat.

  2. Should we keep backward compat with v1 directory structure? Or fully remove the old code? Leaning toward full removal — the v2 schema is different enough that supporting both adds complexity for no real benefit.

  3. Agent storage key format: What should the Hasura key be? E.g. dolos:config:00_Encoder_PyEncoder or just the filename 00_Encoder_PyEncoder.json? Need a namespace to avoid collision with other containers.

  4. The PyEncoder encoder script — what exactly should it do? A pure passthrough (just copies input to output + ENCODING_SUCCESS) is the simplest demo. Or should it do a minimal transformation (XOR, base64) to prove the encoding pipeline works? Leaning toward passthrough for clarity.

  5. Merlin agent compatibility — Dolos is a wrapper, it needs an agent to wrap. We have Merlin installed. Should the v2 docs include a full walkthrough: create Merlin payload → wrap with Dolos → get encoded output?

This plan is awaiting approval before implementation begins.
